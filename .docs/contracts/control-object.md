# Contract: Control objects (`.tpl.cs` / `.gen.cs`)

A MAUI control object is split in two files that compile into one partial class:

- **`X.tpl.cs`** - hand-written. Holds the `protected virtual ...Core` methods (the
  platform action), plus any bespoke members. The element type is `IMauiElement`.
- **`X.gen.cs`** - generated by `Brinell.Generator`. Holds the public wrappers that run
  each `Core` through the call infrastructure. Never edited by hand.

## The Core method pattern

```csharp
// X.tpl.cs
protected virtual void ClickCore(IMauiElement element, int? timeoutMs = null) { ... }
```

The generator emits the public wrapper that finds the element and runs the action as one
call ([call-model](call-model.md), R1/R8):

```csharp
// X.gen.cs  (do not edit)
public TScope Click(int? timeoutMs = null) => RunDoWithElement(e => ClickCore(e, timeoutMs), timeoutMs);
```

- Naming: `{Action}Core` → public `{Action}`. Strip the `Core` suffix.
- First `Core` parameter is always the element; the rest become public arguments.
- `Is*Core` (returning `bool?`) generate the `Is`/`Wait`/`Assert` trio, not an action.

## Act once, then Confirm

An action runs **once** and never repeats ([AD-009](../decisions/ad-009-app-bugs-stay-failures.md),
R0). To wait for its effect, a `Core` method calls `Confirm`, which polls the effect on
its own budget (R3) and never re-runs the action. An effect that never shows - or an
element replaced before it can be read - fails the call and returns
`ConfirmationResult.NotConfirmed` rather than pressing again.

## Broken when

- `X.gen.cs` is edited by hand, or drifts from the generator output (R8).
- A `Core` method retries its own action instead of confirming its effect (R0).
- A `Core` method opens its own wait loop instead of relying on the call's poll (R2).
- The element type in a `.tpl.cs` is a platform driver type rather than `IMauiElement`.

# specification LabelControl

- **id**: SPC-102
- **version**: 1.0
- **created**: January 8, 2026
- **status**: Draft
- **level**: 1
- **requirement**: FR-100, FR-120
- **interfaces**: IControlObject, ITextControlObject

---

## Overview

The Label control represents a read-only text display element. It validates the text retrieval pattern and serves as the base for editable text controls (Entry inherits from ITextControlObject).

---

## behavior

### Core Behaviors (IControlObject)

1. Label can be located by automation ID, name, or other locator strategies
2. Label reports existence state via `IsExists()` returning `bool`
3. Label reports visibility state via `IsVisible()` returning `bool`
4. Label reports enabled state via `IsEnabled()` returning `bool` (typically always true)
5. Label supports waiting for state changes with configurable timeout
6. Label supports assertion methods that throw on failure

### Text Behaviors (ITextControlObject)

7. Label displays text content accessible via `GetText()` returning `string`
8. Label text can be empty string (not null)
9. Label supports text assertion via `AssertText(string? expected, string? message)`
10. Label supports waiting for text via `WaitText(string? expected, int? timeoutMs)`
11. Label supports text matching via `AssertTextMatches(string pattern, string? message)`

### Display Behaviors

12. Label text may wrap across multiple lines
13. Label text may be truncated with ellipsis (platform-dependent)
14. Label may contain formatted text (bold, italic) but `GetText()` returns plain text

---

## boundary

### Text Boundaries

- `GetText()` returns empty string `""` for labels with no text content
- `GetText()` returns plain text even if label contains formatted/rich text
- `GetText()` strips leading/trailing whitespace based on platform behavior
- Multi-line text returns with platform-appropriate line separators

### State Boundaries

- Labels are typically always enabled; `IsEnabled()` returns `true`
- `IsVisible()` returns `false` for labels with visibility=hidden or display=none
- `IsExists()` returns `false` for labels not in DOM/visual tree

### Wait Boundaries

- `WaitText()` uses string equality comparison
- `WaitText()` with null expected value skips wait (nullable skip pattern)
- Wait timeout uses `DefaultWait` from context when not specified

### Assert Boundaries

- `AssertText()` with null expected value skips assertion
- `AssertTextMatches()` uses regex pattern matching
- Assert methods throw `AssertionException` with custom message on failure

## acceptance

### Existence and Location

```gherkin
Scenario: Label is located by automation ID
  Given a page with a label having AutomationId "welcomeLabel"
  When I create a Label control with locator By.AutomationId("welcomeLabel")
  Then IsExists() returns true

Scenario: Label reports non-existence correctly
  Given a page without a label with AutomationId "missingLabel"
  When I create a Label control with locator By.AutomationId("missingLabel")
  Then IsExists() returns false
```

### Text Retrieval

```gherkin
Scenario: GetText returns label content
  Given a label displaying "Welcome to the application"
  When I call GetText()
  Then it returns "Welcome to the application"

Scenario: GetText returns empty string for empty label
  Given a label with no text content
  When I call GetText()
  Then it returns ""

Scenario: GetText returns plain text for formatted label
  Given a label displaying "<b>Bold</b> text" rendered as formatted
  When I call GetText()
  Then it returns "Bold text"
```

### Text Assertions

```gherkin
Scenario: AssertText passes for matching text
  Given a label displaying "Success"
  When I call AssertText("Success", "Text should match")
  Then no exception is thrown

Scenario: AssertText fails for non-matching text
  Given a label displaying "Error"
  When I call AssertText("Success", "Text should match")
  Then AssertionException is thrown with message "Text should match"

Scenario: AssertTextMatches passes for matching pattern
  Given a label displaying "Order #12345"
  When I call AssertTextMatches("Order #\d+", "Should match order pattern")
  Then no exception is thrown
```

### Wait Operations

```gherkin
Scenario: WaitText succeeds when text appears
  Given a label that changes to "Complete" after 500ms
  When I call WaitText("Complete", 2000)
  Then it returns true

Scenario: WaitText fails when text does not appear
  Given a label that stays "Loading..."
  When I call WaitText("Complete", 500)
  Then it returns false
```

### Nullable Skip Pattern

```gherkin
Scenario: AssertText with null skips assertion
  Given any label
  When I call AssertText(null, "Message")
  Then no assertion is performed
  And no exception is thrown

Scenario: WaitText with null skips wait
  Given any label
  When I call WaitText(null, 1000)
  Then method returns immediately
  And returns true
```

## assumption

### Platform Assumptions

1. Underlying automation library provides text retrieval capability
2. Platform correctly reports text content via automation properties
3. Text encoding is handled correctly (UTF-8 support)
4. Line breaks are preserved in multi-line text

### Framework Assumptions

1. TestContext is initialized before label operations
2. Logging is available via `_context.Logger`
3. Timeout settings are configured in `_context.Timeouts`

### Element Assumptions

1. Label has accessible automation properties
2. Label text is programmatically accessible (not just visual)
3. Dynamic text updates are reflected in automation properties

---

## exclusion

### Explicitly Out of Scope

1. **Text editing** — Labels are read-only; see Entry for editable text
2. **Rich text formatting access** — Only plain text is returned
3. **Text selection** — Labels do not support text selection
4. **Hyperlink detection** — Links within labels are not automatically detected
5. **Font/style verification** — Visual properties are not part of behavioral testing
6. **Text measurement** — Width/height of text is platform-specific
7. **Localization verification** — Content validation is test responsibility, not framework

### Deferred to Platform Implementation

1. Text truncation behavior (ellipsis)
2. Text wrapping behavior
3. Right-to-left text handling
4. Accessibility name vs displayed text handling

## Platform Implementation Notes

### MAUI (AppiumElement)

```
Control: Label, Span
Locator: AutomationId, Name, XPath
Text: element.Text or element.GetAttribute("Name")
Note: FormattedText returns concatenated plain text
```

### Blazor (IWebElement)

```
Control: <span>, <label>, <p>, <div> (text display)
Locator: id, data-testid, CSS selector, XPath
Text: element.Text
Note: InnerText excludes hidden elements
```

### WPF (AutomationElement)

```
Control: System.Windows.Controls.Label, TextBlock
Locator: AutomationId, Name
Text: NameProperty or TextPattern.DocumentRange.GetText()
Note: TextBlock may need TextPattern for full text
```

## Method Signatures

### IControlObject Methods

| Method | Signature | Returns | Description |
| ------ | --------- | ------- | ----------- |
| IsExists | `IsExists()` | `bool` | Check if element exists |
| IsVisible | `IsVisible()` | `bool` | Check if element is visible |
| IsEnabled | `IsEnabled()` | `bool` | Check if element is enabled |
| WaitExists | `WaitExists(bool? expected, int? timeoutMs)` | `bool` | Wait for existence state |
| WaitVisible | `WaitVisible(bool? expected, int? timeoutMs)` | `bool` | Wait for visibility state |
| WaitEnabled | `WaitEnabled(bool? expected, int? timeoutMs)` | `bool` | Wait for enabled state |
| AssertExists | `AssertExists(bool? expected, string? message, int? timeoutMs)` | `void` | Assert existence state |
| AssertVisible | `AssertVisible(bool? expected, string? message, int? timeoutMs)` | `void` | Assert visibility state |
| AssertEnabled | `AssertEnabled(bool? expected, string? message, int? timeoutMs)` | `void` | Assert enabled state |

### ITextControlObject Methods

| Method | Signature | Returns | Description |
| ------ | --------- | ------- | ----------- |
| GetText | `GetText()` | `string` | Get displayed text content |
| WaitText | `WaitText(string? expected, int? timeoutMs)` | `bool` | Wait for text value |
| AssertText | `AssertText(string? expected, string? message, int? timeoutMs)` | `void` | Assert text equals expected |
| AssertTextMatches | `AssertTextMatches(string pattern, string? message, int? timeoutMs)` | `void` | Assert text matches regex |

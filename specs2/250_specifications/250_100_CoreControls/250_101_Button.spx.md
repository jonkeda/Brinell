# specification ButtonControl

- **id**: SPC-101
- **version**: 1.0
- **created**: January 8, 2026
- **status**: Draft
- **level**: 1
- **requirement**: FR-100, FR-110
- **interfaces**: IControlObject, IClickableControlObject

---

## Overview

The Button control represents a clickable UI element that triggers an action when activated. It is the simplest interaction control and validates the click flow pattern for the entire framework.

---

## behavior

### Core Behaviors (IControlObject)

1. Button can be located by automation ID, name, or other locator strategies
2. Button reports existence state via `IsExists()` returning `bool`
3. Button reports visibility state via `IsVisible()` returning `bool`
4. Button reports enabled state via `IsEnabled()` returning `bool`
5. Button supports waiting for state changes with configurable timeout
6. Button supports assertion methods that throw on failure

### Click Behaviors (IClickableControlObject)

7. Button can be clicked via `Click()` method
8. Click triggers the associated action/command
9. Button supports double-click via `DoubleClick()` method
10. Button displays text content accessible via inherited `GetText()` (optional)

### State Behaviors

11. Button can be in enabled or disabled state
12. Button can be visible or hidden
13. Button can have focus
14. Disabled button appears visually distinct (platform-dependent)

---

## boundary

### Click Boundaries

- Click on disabled button does nothing and does not throw error
- Click on hidden button waits for visibility up to timeout, then throws `TimeoutException`
- Click on non-existent button waits for existence up to timeout, then throws `ElementNotFoundException`
- Double-click is distinct from two single clicks (fires different events)
- Rapid successive clicks are handled by platform (no framework debounce)

### State Boundaries

- `IsExists()` returns `false` for elements not in DOM/visual tree
- `IsVisible()` returns `false` for elements with visibility=hidden, display=none, or off-screen
- `IsEnabled()` returns `false` for elements with disabled attribute or IsEnabled=false

### Wait Boundaries

- Wait methods use `DefaultWait` timeout from context when timeout parameter is null
- Wait methods return `true` if condition met within timeout, `false` otherwise
- Minimum timeout is 0 (immediate check, no wait)
- Maximum timeout is limited by platform driver settings

### Assert Boundaries

- Assert methods throw `AssertionException` with custom message when condition not met
- Assert methods with null expected value skip assertion (nullable skip pattern)
- Assert methods wait for condition up to timeout before failing

## acceptance

### Existence and Location

```gherkin
Scenario: Button is located by automation ID
  Given a page with a button having AutomationId "submitButton"
  When I create a Button control with locator By.AutomationId("submitButton")
  Then IsExists() returns true

Scenario: Button reports non-existence correctly
  Given a page without a button with AutomationId "missingButton"
  When I create a Button control with locator By.AutomationId("missingButton")
  Then IsExists() returns false
```

### Click Actions

```gherkin
Scenario: Clicking enabled button triggers action
  Given a visible enabled button
  When I call Click()
  Then the button's associated action is triggered

Scenario: Clicking disabled button does nothing
  Given a visible disabled button
  When I call Click()
  Then no action is triggered
  And no exception is thrown

Scenario: Clicking hidden button waits then succeeds
  Given a button that becomes visible after 500ms
  And a timeout of 2000ms
  When I call Click()
  Then the click succeeds after the button becomes visible
```

### State Verification

```gherkin
Scenario: IsEnabled returns correct state
  Given an enabled button
  When I call IsEnabled()
  Then it returns true

Scenario: IsVisible returns correct state
  Given a hidden button
  When I call IsVisible()
  Then it returns false
```

### Wait Operations

```gherkin
Scenario: WaitExists succeeds when button appears
  Given a button that appears after 500ms
  When I call WaitExists(true, 2000)
  Then it returns true

Scenario: WaitExists fails when button does not appear
  Given a button that never appears
  When I call WaitExists(true, 500)
  Then it returns false
```

### Assert Operations

```gherkin
Scenario: AssertExists passes for existing button
  Given an existing button
  When I call AssertExists(true, "Button should exist")
  Then no exception is thrown

Scenario: AssertExists fails for missing button
  Given a non-existing button
  When I call AssertExists(true, "Button should exist")
  Then AssertionException is thrown with message "Button should exist"
```

## assumption

### Platform Assumptions

1. Underlying automation library (Appium/Selenium/FlaUI) supports click action
2. Platform provides accessible automation ID or locator mechanism
3. Click events propagate correctly through platform event system
4. Disabled state is correctly reported by automation framework

### Framework Assumptions

1. TestContext is initialized before button operations
2. Logging is available via `_context.Logger`
3. Timeout settings are configured in `_context.Timeouts`
4. Platform driver is connected and operational

### Element Assumptions

1. Button has accessible automation properties
2. Button click area is not obscured by other elements
3. Button is within scrollable viewport or can be scrolled into view

---

## exclusion

### Explicitly Out of Scope

1. **Long-press gestures** — Covered in Level 4 mobile-specific (ILongPressControlObject)
2. **Drag operations** — Not applicable to button control
3. **Right-click/context menu** — Platform-specific, may be added in future level
4. **Keyboard activation** — Handled by platform, not framework responsibility
5. **Visual styling verification** — Not part of behavioral testing
6. **Animation state** — Platform-specific, not abstracted
7. **Touch gestures beyond tap** — Level 4 mobile-specific

### Deferred to Platform Implementation

1. Scroll-into-view behavior before click
2. Focus management during click
3. Click coordinate calculation
4. Event bubbling behavior

## Platform Implementation Notes

### MAUI (AppiumElement)

```
Control: Button, ImageButton
Locator: AutomationId, Name, XPath
Click: element.Click()
Text: element.Text or element.GetAttribute("Name")
```

### Blazor (IWebElement)

```
Control: <button>, <input type="button">, <a> (styled as button)
Locator: id, data-testid, CSS selector, XPath
Click: element.Click()
Text: element.Text or element.GetAttribute("value")
```

### WPF (AutomationElement)

```
Control: System.Windows.Controls.Button
Locator: AutomationId, Name
Click: InvokePattern.Invoke()
Text: NameProperty or ValuePattern.Value
```

## Method Signatures

### IControlObject Methods

| Method | Signature | Returns | Description |
| ------ | --------- | ------- | ----------- |
| IsExists | `IsExists()` | `bool` | Check if element exists |
| IsVisible | `IsVisible()` | `bool` | Check if element is visible |
| IsEnabled | `IsEnabled()` | `bool` | Check if element is enabled |
| WaitExists | `WaitExists(bool? expected, int? timeoutMs)` | `bool` | Wait for existence state |
| WaitVisible | `WaitVisible(bool? expected, int? timeoutMs)` | `bool` | Wait for visibility state |
| WaitEnabled | `WaitEnabled(bool? expected, int? timeoutMs)` | `bool` | Wait for enabled state |
| AssertExists | `AssertExists(bool? expected, string? message, int? timeoutMs)` | `void` | Assert existence state |
| AssertVisible | `AssertVisible(bool? expected, string? message, int? timeoutMs)` | `void` | Assert visibility state |
| AssertEnabled | `AssertEnabled(bool? expected, string? message, int? timeoutMs)` | `void` | Assert enabled state |

### IClickableControlObject Methods

| Method | Signature | Returns | Description |
| ------ | --------- | ------- | ----------- |
| Click | `Click()` | `void` | Perform single click |
| DoubleClick | `DoubleClick()` | `void` | Perform double click |

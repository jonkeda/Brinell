# specification EntryControl

- **id**: SPC-103
- **version**: 1.0
- **created**: January 8, 2026
- **status**: Draft
- **level**: 1
- **requirement**: FR-100, FR-130
- **interfaces**: IControlObject, ITextControlObject, IEditableTextControlObject

---

## Overview

The Entry control represents a single-line text input field. It extends ITextControlObject with editing capabilities, validating the interface inheritance pattern (ITextControlObject → IEditableTextControlObject).

---

## behavior

### Core Behaviors (IControlObject)

1. Entry can be located by automation ID, name, or other locator strategies
2. Entry reports existence state via `IsExists()` returning `bool`
3. Entry reports visibility state via `IsVisible()` returning `bool`
4. Entry reports enabled state via `IsEnabled()` returning `bool`
5. Entry supports waiting for state changes with configurable timeout
6. Entry supports assertion methods that throw on failure

### Text Behaviors (ITextControlObject - Inherited)

7. Entry displays text content accessible via `GetText()` returning `string`
8. Entry text can be empty string (not null)
9. Entry supports text assertion via `AssertText(string? expected, string? message)`
10. Entry supports waiting for text via `WaitText(string? expected, int? timeoutMs)`
11. Entry supports text matching via `AssertTextMatches(string pattern, string? message)`

### Editable Text Behaviors (IEditableTextControlObject)

12. Entry accepts text input via `Enter(string text)` method
13. Entry can be cleared via `Clear()` method
14. Entry supports setting text directly via `SetText(string text)` (Clear + Enter)
15. Entry can have placeholder text (not returned by `GetText()`)
16. Entry supports read-only state (enabled but not editable)

### Input Behaviors

17. `Enter()` appends text to existing content
18. `SetText()` replaces existing content
19. Entry may have maximum length constraint (platform-dependent)
20. Entry may have input validation (masked input, numeric only, etc.)

## boundary

### Text Entry Boundaries

- `Enter("")` does nothing (appends empty string)
- `Enter()` on disabled entry does nothing and does not throw
- `Enter()` on read-only entry does nothing and does not throw
- `SetText()` clears then enters, even if entry is empty
- `Clear()` on empty entry does nothing

### Text Retrieval Boundaries

- `GetText()` returns current value, not placeholder text
- `GetText()` returns empty string `""` for empty entry (not placeholder)
- `GetText()` for password entry may return masked value or empty (platform-dependent)

### State Boundaries

- `IsEnabled()` returns `false` for disabled entries
- Read-only entries return `IsEnabled() = true` but do not accept input
- `IsVisible()` returns `false` for entries with visibility=hidden or display=none

### Wait Boundaries

- `WaitText()` uses string equality comparison
- Wait timeout uses `DefaultWait` from context when not specified
- `WaitText()` with null expected value skips wait (nullable skip pattern)

### Assert Boundaries

- `AssertText()` with null expected value skips assertion
- Assert methods throw `AssertionException` with custom message on failure

### Input Length Boundaries

- Maximum length is enforced by platform, not framework
- Text exceeding max length is truncated (platform-dependent)
- `Enter()` does not validate length before entering

## acceptance

### Existence and Location

```gherkin
Scenario: Entry is located by automation ID
  Given a page with an entry having AutomationId "usernameEntry"
  When I create an Entry control with locator By.AutomationId("usernameEntry")
  Then IsExists() returns true
```

### Text Entry

```gherkin
Scenario: Enter appends text to entry
  Given an empty entry
  When I call Enter("Hello")
  Then GetText() returns "Hello"

Scenario: Enter appends to existing text
  Given an entry containing "Hello"
  When I call Enter(" World")
  Then GetText() returns "Hello World"

Scenario: SetText replaces existing text
  Given an entry containing "Old Value"
  When I call SetText("New Value")
  Then GetText() returns "New Value"

Scenario: Clear removes all text
  Given an entry containing "Some text"
  When I call Clear()
  Then GetText() returns ""
```

### Text Retrieval

```gherkin
Scenario: GetText returns current value
  Given an entry containing "Test Value"
  When I call GetText()
  Then it returns "Test Value"

Scenario: GetText returns empty string for empty entry
  Given an empty entry with placeholder "Enter name..."
  When I call GetText()
  Then it returns ""
```

### Disabled and Read-Only

```gherkin
Scenario: Enter on disabled entry does nothing
  Given a disabled entry containing "Original"
  When I call Enter("New")
  Then GetText() still returns "Original"
  And no exception is thrown

Scenario: Enter on read-only entry does nothing
  Given a read-only entry containing "Read Only"
  When I call Enter("Change")
  Then GetText() still returns "Read Only"
  And no exception is thrown
```

### Wait and Assert Operations

```gherkin
Scenario: WaitText succeeds when text matches
  Given an entry that receives "Complete" via binding after 500ms
  When I call WaitText("Complete", 2000)
  Then it returns true

Scenario: AssertText passes for matching text
  Given an entry containing "Expected"
  When I call AssertText("Expected", "Text should match")
  Then no exception is thrown

Scenario: AssertText fails for non-matching text
  Given an entry containing "Actual"
  When I call AssertText("Expected", "Text should match")
  Then AssertionException is thrown with message "Text should match"
```

### Nullable Skip Pattern

```gherkin
Scenario: AssertText with null skips assertion
  Given any entry
  When I call AssertText(null, "Message")
  Then no assertion is performed
  And no exception is thrown
```

## assumption

### Platform Assumptions

1. Underlying automation library supports text entry actions
2. Platform correctly reports text value via automation properties
3. Clear action is supported by automation framework
4. Keyboard input is simulated correctly

### Framework Assumptions

1. TestContext is initialized before entry operations
2. Logging is available via `_context.Logger`
3. Timeout settings are configured in `_context.Timeouts`

### Element Assumptions

1. Entry has accessible automation properties
2. Entry accepts text input when enabled and not read-only
3. Entry value updates are reflected in automation properties

---

## exclusion

### Explicitly Out of Scope

1. **Multi-line text** — Entry is single-line; multi-line uses TextArea/Editor
2. **Input masking** — Masked input (phone, credit card) is platform-specific
3. **Input validation** — Validation rules are app logic, not framework concern
4. **Autocomplete suggestions** — Dropdown suggestions are separate controls
5. **Clipboard operations** — Copy/paste is platform-specific
6. **Undo/redo** — Text history is platform-specific
7. **Password visibility toggle** — App-specific UI element
8. **Virtual keyboard handling** — Mobile keyboard management is platform-specific

### Deferred to Platform Implementation

1. Focus management before typing
2. Scroll into view behavior
3. Input method editor (IME) handling
4. Special character entry

## Platform Implementation Notes

### MAUI (AppiumElement)

```
Control: Entry, Editor (single-line mode), SearchBar
Locator: AutomationId, Name, XPath
GetText: element.Text
Enter: element.SendKeys(text)
Clear: element.Clear()
SetText: element.Clear(); element.SendKeys(text)
Note: Placeholder in element.GetAttribute("Placeholder")
```

### Blazor (IWebElement)

```
Control: <input type="text">, <input type="email">, <input type="password">, etc.
Locator: id, data-testid, name, CSS selector, XPath
GetText: element.GetAttribute("value")
Enter: element.SendKeys(text)
Clear: element.Clear()
SetText: element.Clear(); element.SendKeys(text)
Note: element.Text returns empty for input elements; use GetAttribute("value")
```

### WPF (AutomationElement)

```
Control: System.Windows.Controls.TextBox
Locator: AutomationId, Name
GetText: ValuePattern.Value
Enter: ValuePattern.SetValue(existingValue + text) or SendKeys
Clear: ValuePattern.SetValue("")
SetText: ValuePattern.SetValue(text)
Note: RichTextBox uses TextPattern instead
```

## Method Signatures

### IControlObject Methods

| Method | Signature | Returns | Description |
| ------ | --------- | ------- | ----------- |
| IsExists | `IsExists()` | `bool` | Check if element exists |
| IsVisible | `IsVisible()` | `bool` | Check if element is visible |
| IsEnabled | `IsEnabled()` | `bool` | Check if element is enabled |
| WaitExists | `WaitExists(bool? expected, int? timeoutMs)` | `bool` | Wait for existence state |
| WaitVisible | `WaitVisible(bool? expected, int? timeoutMs)` | `bool` | Wait for visibility state |
| WaitEnabled | `WaitEnabled(bool? expected, int? timeoutMs)` | `bool` | Wait for enabled state |
| AssertExists | `AssertExists(bool? expected, string? message, int? timeoutMs)` | `void` | Assert existence state |
| AssertVisible | `AssertVisible(bool? expected, string? message, int? timeoutMs)` | `void` | Assert visibility state |
| AssertEnabled | `AssertEnabled(bool? expected, string? message, int? timeoutMs)` | `void` | Assert enabled state |

### ITextControlObject Methods (Inherited)

| Method | Signature | Returns | Description |
| ------ | --------- | ------- | ----------- |
| GetText | `GetText()` | `string` | Get current text content |
| WaitText | `WaitText(string? expected, int? timeoutMs)` | `bool` | Wait for text value |
| AssertText | `AssertText(string? expected, string? message, int? timeoutMs)` | `void` | Assert text equals expected |
| AssertTextMatches | `AssertTextMatches(string pattern, string? message, int? timeoutMs)` | `void` | Assert text matches regex |

### IEditableTextControlObject Methods

| Method | Signature | Returns | Description |
| ------ | --------- | ------- | ----------- |
| Enter | `Enter(string text)` | `void` | Append text to current value |
| Clear | `Clear()` | `void` | Clear all text |
| SetText | `SetText(string text)` | `void` | Replace text (Clear + Enter) |

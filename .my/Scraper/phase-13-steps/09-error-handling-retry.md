# Step 13.9 — Error Handling & Recovery

## Objective

Define and implement consistent retry, fallback, and surface-to-UI behavior across all pipeline stages so that one failed stage does not abort the workflow.

## Dependencies

- Steps 13.1 – 13.8

## Implementation

### Retry matrix

| Stage | Retry trigger | Max retries | Fallback |
|---|---|---|---|
| ControlObject Analysis (LLM) | JSON parse fail / schema invalid | 1 (with feedback prompt) | Return partial result: `Proposals=[]`, surface local groups only |
| ControlObject Generation (LLM) | Roslyn or registry validation error | 1 | Mark proposal `GenerationStatus=Failed`, continue with next |
| PageObject Generation (LLM) | Validation error | 1 | Persist `PageGenerationResult` with `Status=Error` + errors |
| Roslyn validation | — | — | No retry; surface errors in UI for manual edit |
| Corpus tool calls | I/O exception | 2 (exponential 200ms/500ms) | Return empty array; LLM works with reduced context |
| Copilot SDK 401/403 | Auth fail | 0 | Raise `AuthRequired` event; abort current stage |
| Copilot SDK rate limit (429) | Rate limit | 3 (respect `Retry-After`) | After max, return `RateLimited` error to UI |
| Copilot SDK token-limit | Prompt too large | 1 (truncate DOM) | If still fails, mark stage error |

### Common failure handling utility

```csharp
public class LlmRetryHelper
{
    public async Task<T> WithRetryAsync<T>(
        Func<string, CancellationToken, Task<string>> call,
        string initialPrompt,
        Func<string, (bool ok, T? result, string? error)> validate,
        int maxRetries = 1,
        CancellationToken ct = default)
    {
        var prompt = initialPrompt;
        for (int attempt = 0; attempt <= maxRetries; attempt++)
        {
            var response = await call(prompt, ct);
            var (ok, result, error) = validate(response);
            if (ok) return result!;

            _logger.LogWarning("LLM attempt {Attempt} failed: {Error}", attempt, error);
            prompt = initialPrompt + "\n\nPrevious attempt had errors:\n" + error +
                     "\nFix these errors and respond again.";
        }
        throw new LlmValidationException("Max retries exceeded");
    }
}
```

### Failure surfacing

| Stage | Where surfaced |
|---|---|
| Analysis | Control Objects tab — toast + log entry; tab still loads existing controls |
| Control gen | Per-card status badge "Failed" + error tooltip; Regenerate button enabled |
| Page gen | Per-row status icon "Error" + Validation panel shows error list |
| Auth | Modal "Sign in to GitHub" prompt + Settings tab status |
| Rate limit | Toast "Rate limited — retry in N seconds" |

### Token-limit truncation strategy

For PageObject generation:

1. Estimate prompt token count (chars / 4 heuristic).
2. If > model limit:
   - Truncate to actionable elements only (drop `<script>`, `<style>`, comments, deeply-nested non-actionable nodes).
   - Drop pretty-printing whitespace.
   - If still too large, paginate: split actionable elements into chunks, generate per-chunk, merge.

### Cancellation

- All pipeline methods accept `CancellationToken`.
- UI exposes a "Cancel" button on long-running operations (Analyze, Generate All) that propagates the token.
- On cancellation, persist whatever has completed; UI shows "Cancelled — N of M completed".

### Logging conventions

- `Information`: stage start/end, retry attempts.
- `Warning`: validation failures, rate-limit waits, fallback applied.
- `Error`: max retries exceeded, auth failure.
- All entries include `SiteId`, stage name, and a correlation `RunId` (Guid generated by `PipelineOrchestrator` per run).

### Tests

- Unit: `LlmRetryHelper` with simulated success / fail / fail-then-success.
- Unit: token-limit truncation reduces prompt size while preserving actionable elements.
- Integration: control gen with deliberately broken validator returns failed proposal without aborting subsequent ones.
- Integration: page gen rate-limit retries N times then surfaces error.

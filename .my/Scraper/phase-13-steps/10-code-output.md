# Step 13.10 — Code Output Service

## Objective

Implement `CodeOutputService` — writes generated ControlObjects and PageObjects to disk as a buildable C# project structure ready for the consumer to compile.

## Dependencies

- Step 13.2, 13.4 (generated artifacts available)
- Phase 7 spec (project output design)

## Implementation

### Files

- `Services/CodeOutputService.cs`
- `Templates/ProjectFile.csproj.template`

### Service contract

```csharp
public class CodeOutputService
{
    public async Task WriteProjectAsync(
        string outputPath,
        string targetNamespace,
        IReadOnlyList<GeneratedControl> controls,
        IReadOnlyList<PageGenerationResult> pages,
        CancellationToken ct = default);
}
```

### Output layout

```
{outputPath}/
├─ {Namespace}.csproj
├─ Directory.Build.props          (optional, copied from template)
├─ Controls/
│   ├─ LoginFormContainer.cs
│   ├─ MainNavContainer.cs
│   └─ ...
├─ Pages/
│   ├─ LoginPage.cs
│   ├─ DashboardPage.cs
│   └─ ...
└─ Pages/Containers/              (only if any inline containers were generated)
    └─ {PageName}.{ContainerName}.cs
```

### Generation rules

1. **csproj** — from template, with:
   - `<TargetFramework>net9.0</TargetFramework>`
   - `<RootNamespace>{targetNamespace}</RootNamespace>`
   - PackageReferences: `Brinell.Core`, `Brinell.Html` (or `Brinell.Maui`, etc., based on settings).
   - SDK: `Microsoft.NET.Sdk`.
2. **Controls/** — one file per `GeneratedControl`, file name = `{control.Name}.cs`. Wrap in `namespace {targetNamespace}.Controls`.
3. **Pages/** — one file per `PageGenerationResult.MainCode`. File name = `{result.ClassName}.cs`. Namespace = `{targetNamespace}.Pages`.
4. **Pages/Containers/** — one file per inline container code. File name = `{result.ClassName}.{ContainerClassName}.cs`. Namespace = `{targetNamespace}.Pages.Containers`.
5. Existing files are **overwritten**. Files for entities no longer present are **deleted** (clean output).

### Header comment per file

```csharp
// <auto-generated>
//   Generated by Brinell.Scraper on {UtcNow:O}
//   Source: {snapshot URL or "ControlObject analysis"}
//   Confidence: {confidence}%
//   Do not edit manually — regenerate from the scraper UI.
// </auto-generated>
```

### Idempotency

- Re-running `WriteProjectAsync` on an unchanged dataset produces byte-identical output (deterministic ordering: alphabetical by class name).
- File deletes are scoped: only files inside `Controls/`, `Pages/`, `Pages/Containers/` are touched. User-added files elsewhere in `outputPath` are preserved.

### Validation before write

- Reject if `outputPath` is empty, root, or inside the corpus directory.
- Create directories with `Directory.CreateDirectory`.
- Use `FileShare.None` write to avoid partial writes; write to `*.tmp` then `Move` for atomicity.

### Logging

- `Wrote project to {outputPath}: {ControlsCount} controls, {PagesCount} pages, {ContainersCount} containers`
- Per-file: `Trace` level only.

### DI registration

```csharp
services.AddSingleton<CodeOutputService>();
```
